# ADR-002 — Source distribution and audited dependency locks

Accepted for foundation 0.1.2, 2026-10-18. Supersedes ADR-001's pending-lock caveat;
all READ_ONLY and integration-gate decisions remain in force.

The complete dependency graph is resolved by uv 0.12.6 and exported as hashed
runtime/development requirements. CI verifies lock/export consistency, installs
with `--require-hashes`, runs a Windows/Linux Python 3.11/3.12 matrix and installs
the wheel in a separate environment outside the source tree. Runtime dependency
advisories are checked without exemptions. Build tooling is in the development
lock. Docker installs the same runtime export but its base image is not digest
pinned; image reproducibility and container validation remain separate gates.

Source integrity uses LF for authored text and byte-preserved immutable v1.2
evidence. The source manifest excludes secrets and local/generated outputs;
maintained QA and review records live in versioned architecture documentation.
An exporter copies only verified manifest files into a fresh directory, without
Git credentials, virtual environments or ignored local reports.

Dataset split v3 uses connected components of dialogue groups and scenario
families. This can leave a small dataset in a single partition, which is reported
as not evaluation-ready. It must not be repaired by splitting the same family
across partitions or by fabricating more scenario families. Near-duplicate
review and model experiment manifests are still required before training.

The baseline conversation contract adds optional `active_intent` for task
continuation. Client state remains untrusted preference context; no identity,
ownership, live facts or authorization can be inferred from it. Typed CLEAR and
REMOVE affect only supported conversation slots. Candidate reference resolution,
full ontology coverage, purchase quotas and snapshot freshness remain integration
work before a live recommender can be exposed.
