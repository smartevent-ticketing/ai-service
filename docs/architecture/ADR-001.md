# ADR-001 — Clean Architecture, immutable v1.2, runtime READ_ONLY

Status: ACCEPTED for local bootstrap. Date: 2026-10-18.

## Decisions

1. Python package `smartevent_ai` has inward dependencies. Domain implements value types, dialogue state and deterministic optimization. Application defines protocols/use cases. Outbound adapters carry transport/provider details; inbound adapters expose HTTP. Composition root injects implementations.
2. Preserve the **exact original v1.2 ZIP content** in `docs/contexts/v1.2` (49 source files). Original contracts contain known audit defects; do not silently rewrite historical evidence. Runtime authoritative contracts are `configs/runtime_tool_registry.yaml` and `configs/implementation_gates.yaml`. All tools disabled until review of integration evidence.
3. Separate *public product capabilities* from *approved runtime tools*. A controller declaring GET does **not** imply side-effect-free, public, or authorized access to child event data.
4. Use deterministic offline Vietnamese NLU as **baseline only**. Future Qwen3-1.7B/QLoRA adapter must implement `LanguageUnderstanding` protocol and output strictly validated `Understanding`. RAG/JEV planned, not implemented; no fake success.
5. No business DB persistence or write endpoints. AI state is returned to clients statelessly. This is not a secure user session, so authenticated reads remain disabled until an auditable BFF self-only delegation is built.
6. The runtime response contract requires strict field validation after allowlist projection, refuses unpublished event rows, preserves pagination (`page/size/totalElements/totalPages/last`), reports partiality and filters unavailable seats before limits.
7. `SafeBackendTransport` alone controls origin, method, timeout, redirect, byte cap, query serialization; no caller can choose a backend URL. No retries and no credentials in current bootstrap.
8. CI is configured to gate code syntax, Ruff, Mypy, unit/contracts/HTTP security tests, immutable source integrity and wheel build on GitHub. It has NOT been executed remotely in this task. The existence of passing mocked tests does not substitute for real backend integration or load tests.

## Rejected

- An LLM with direct network/SQL tool access.
- Mutation after user confirmation, including reservation, order, payment or refund review.
- Copying V1.2 reference executor into production without fixing its known findings.
- Automatic gate PASS based on unit tests or inferred safety.

## Constraints/future work

Backend event-child `PUBLISHED_ONLY` authorization, customer-self BFF authentication, QR-safe projection, approved RAG corpus, model training and live E2E are unimplemented release blockers. `docs/architecture/RELEASE_GATES.md` tracks them explicitly.

## Reproducibility caveat

Fully hash-locked transitive dependency resolution is not yet available in this offline environment. Direct dependency versions are pinned; creating/validating a wheel lock on an internet-enabled CI runner is a prerequisite for strict rebuild reproducibility.
